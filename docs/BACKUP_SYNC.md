# 加密完整备份与设备间同步

入口：顶部“⇅”，直接进入“导入 / 导出”。本功能服务于 `NP_MODE=local`。同一网站的节点配置由服务端共享，无需在浏览器之间导入。不同的独立部署用备份文件同步；这不是后台自动双向同步。

## 导出

1. 密码可选：留空导出未加密完整 JSON；填写任意长度密码则加密。它与网站登录密码无关。
2. 点击“导出文件”。历史默认包含；“更多选项”可关闭历史或只导出不含凭据的节点清单。
3. 保存文件；加密时同时保管密码，系统无法找回。未加密文件可直接读取其中的登录凭据。

包含：稳定节点 ID、名称/IP/位置/标签、普通连接、自定义线路、SSH 与 frp 连接档案、中转关系、测试方法、VLESS 链接、SSH 密码、配置中明确引用且可读取的私钥、对应 SSH 地址的主机指纹、供应商账号凭据、测试选项与周期，以及可选本地/设备测量记录。还包含发起导出的浏览器的可迁移显示偏好和测试范围。

仅读取节点引用的私钥和对应 SSH 地址的指纹，不复制整个 `.ssh` 目录。读取失败会列出警告，不能将这份备份当作凭据完整。ssh-agent、硬件安全密钥、私钥解锁状态、SSH 跳板环境及外部依赖不能复制；必要时在新主机重新配置。

不属于本地模式配置迁移的内容：项目源码与运行依赖、TLS/网站登录密码、服务进程及环境变量、原系统 SSH 配置，以及旧版常驻探针的 `history/` 时序文件。新服务需先安装同版本或兼容版本。备份最多 6 MiB 明文；超限明确报错，可关闭测量历史后导出配置。

## 导入及后续更新

1. 在目标服务打开相同入口，选择文件。只有加密文件才显示密码输入框。
2. 默认合并更新。需要同步删除时，打开“更多选项”，勾选“完全替换现有节点”。
3. 相同 ID 可选择使用备份配置或保留目标配置；覆盖同步始终使用备份配置。预览会逐节点列出新增、更新、保留和删除。
4. 点击“导入文件”，核对弹出的新增、更新、删除摘要，再确认。展开详情可检查各节点和缺项警告。
5. 每次修改后重新导出，在其他独立服务重复此流程即可更新。同 ID 不重复新增。合并不会传播删除；需要传播删除时使用覆盖同步。

按稳定 ID 匹配，不按相同 IP 匹配，避免把多个 frp 后端误合并。以前用基础 JSON 导入过的节点可能有不同 ID，不自动猜测对应关系；可用完整备份覆盖同步建立统一 ID。

“使用备份配置”是用户选择的覆盖规则，不声称能自动解决双方编辑冲突。导入预览后目标端配置或凭据变化，会拒绝应用并要求重新预览。

## 环境与历史

- 自动测量导入后保持关闭，周期和范围可恢复；用户检查网卡后自行开启。
- 保留目标端的物理网卡、部署位置、网站地址、登录权限、注册配置与告警通知设置。它们不会随文件自动启用。
- 当前浏览器设备 ID、系统、名称、位置、网卡、登录 Token 和待执行测试令牌不迁移。
- 原主机的 `local` 测量转成“导入 · 原主机”这一独立起点。设备与 VPS 互测结果保留来源和时间，不伪装成新主机测试结果。同一服务的回滚备份可恢复自身记录。
- 测量期间拒绝导入。导入不运行网络测试、不安装探针、不修改系统代理或路由。
- 私钥和指纹写入目标数据目录的 `imported-ssh/`，权限 0600；凭据写入 `vaults/`，权限 0600；连接引用自动调整。保持 SSH 主机密钥严格检查。跳板的本机认证与指纹仍需核对。

## 回滚与实现

每次应用前自动保存回滚文件，界面提供下载按钮。文件也保存在数据目录 `backups/<编号>.json`，加密导入使用原密码保护；无密码导入的回滚文件也不加密。需要撤销时用回滚文件再次预览并覆盖同步。回滚会恢复节点配置和凭据，仍遵守目标环境隔离、历史合并及自动测量关闭规则，不是系统磁盘快照。

设置密码时采用 AES-256-GCM 认证加密；每份文件随机 salt 与 nonce；固定 scrypt 参数 N=32768、r=8、p=1 派生密钥。错误密码、损坏、非法引用、未知格式或超限文件拒绝写入。密码仅用于当前请求处理，不记录日志。加解密在当前服务端进行，经 HTTPS 传输；这不是对当前服务管理员保密的端到端保险箱。

导入先校验和预览，写入新凭据/私钥文件，再通过数据库原子替换切换引用。写入失败保留原数据库。数据目录需按原部署规则备份；加密回滚与旧凭据文件不会自动清理。

基础 JSON 与 CSV 使用同一界面导入，服务端通过 `basic-preview` / `basic-apply` 转换成可预览与回滚的导入，保留已有同 ID 节点的凭据。

管理员 API：`POST /api/backups/export`、`POST /api/backups/preview`、`POST /api/backups/apply`、`GET /api/backups/rollback/:id`。三种 POST 接口均需管理员认证，无跨源豁免；预览返回摘要和配置 revision，不返回解密后的凭据。apply 必须提交同一文件、密码、选项及预览 revision。

# 智能体节点接入流程

适用请求：新增 VPS、导入 VLESS、接入 frp、添加中转、更新登录信息，或“帮我配置节点”。仓库根 AGENTS.md 要求这些任务主动读取本文件。

状态：0.3.0 已提供本地接入接口。先读 [本地测量方案](../LOCAL_MONITORING_PLAN.md)。操作前检查 `GET /api/local` 的 `schemaVersion` 和 `enabled`，不向旧版本盲目提交新字段。

## 1. 先确认当前能力

1. 读取仓库根 AGENTS.md 和运行版本。检查当前实现是否支持本地测量、连接档案、任务 API 和配置版本。
2. 查看当前节点、连接关系和调度设置。只读取任务所需信息，不输出已有凭据。
3. 若能力尚未实现，明确报告缺项。可以整理不含密钥的接入清单，不伪造成功、不自行改用常驻 VPS Agent。
4. 确认实际测量电脑。不得把远端 Hub 的结果标成用户当前设备的结果。

## 2. 收集最少的信息

优先使用用户已提供的信息和本机现有 SSH 配置。只询问缺失项，不重复询问已授权操作。

| 类别 | 所需信息 |
| --- | --- |
| 本地设备 | 运行电脑、系统、正在使用的 VPN/TUN/代理 |
| VPS | 显示名称、地址、可选地区、可测试服务端口 |
| SSH | 已有别名，或地址/端口/用户名；密钥路径或凭据引用；必要的跳板 |
| VLESS | 链接所在本地文件或用户提供的链接、所属节点、已知入口和落地 |
| frp | 已知 frps/frpc 节点、映射入口、后端；或可读取配置的登录方式和路径 |
| 中转 | 已知节点顺序、每段协议、用途：管理或业务 |

- 不要求用户粘贴私钥。使用现有 SSH 别名、ssh-agent、本地密钥或系统凭据存储。
- 自动 SSH 检测需要无人值守认证。只有交互密码或临时解锁条件时，明确标记自动测试尚不可用；不把密码写进命令行。
- VLESS 链接包含访问凭据。不在总结、日志、截图或 Git 中完整复述。
- “不知道”是有效输入。先从已授权的配置中查找，无法确认的字段保留未知。

## 3. 读取和确认拓扑

1. 在授权的机器和配置范围内检查 SSH、frp、代理出入站及路由规则。按需读取，不全盘搜索凭据。
2. 读取配置所需的 SSH 登录属于配置工作，但不会自动授权延迟、路由或带宽测试。
3. 只使用已信任的 SSH 主机密钥；首次未知密钥建立信任，密钥发生变化时停止该连接并核对，不跳过校验。
4. 为物理/虚拟机器分配稳定 ID，为 SSH、VLESS、frp 等分配端点。多个端点可以属于同一设备。
5. 不按相同入口 IP 合并 frp 后端。核实不同端口、不同后端和容器网络的含义。
6. 分别记录管理链和业务链。SSH 跳板不是业务中转的证据；frp 管理入口不是 VLESS 入口的证据。
7. 记录配置出处、读取时间及未知项。不要用地理距离推测实际线路。

## 4. 保存节点

1. 优先使用当前版本真实存在的管理 API/导入接口。先读取 schema 与现有对象，只提交必要字段。
2. 根据稳定 ID、SSH 身份、端点及用户给定名称检查重复；存在歧义才询问。不要覆盖无关节点。
3. 凭据写入受限的本地存储，公开记录仅保存引用。确认不会进入版本控制和普通导出。
4. 新节点默认不进入现有自动任务范围。保持用户原有手动/自动模式、周期和线路分析开关。
5. 新拓扑标记“已配置”或“规划”，未经实际验证不标记“已验证”。未知地理位置不阻止节点保存。
6. 只在用户要求时把新节点加入自动范围；加入不立即触发测试，等待下一次正常轮次。
7. 不直接编辑运行中的 db.json。缺少接口时报告实现缺项；任何离线数据迁移必须先备份并避免与 Hub 写入竞争。

## 5. 验证规则

- 用户仅要求新增或配置：验证本地结构、引用、参数和密钥文件权限，不自动运行网络测试。
- 用户明确要求“测一下”“验证连通”或“一轮测试”：按范围执行一轮，结果记录方法和方向，不自动开启定时任务。
- 用户要求开启自动测试：确定轮次周期和任务范围，然后保存。周期未给出时询问，不自行选择并开启。
- 线路分析独立开关。用户开启线路分析不等于开启自动测试；随自动轮次分析也需明确配置。
- frp 端口可连接后仍需验证后端服务。VLESS 应通过指定出站访问测试目标。公网 ping 与代理体验分别展示。
- SSH 远程执行固定、有限次数、有总超时的命令。测试结束不留下脚本服务、后台任务、定时器或自启动项。
- 缺依赖时先报告。不能把安装依赖、修改防火墙、重启业务或安装常驻探针作为测试的隐式步骤。
- 不运行带宽压测，除非用户另有明确要求。

## 6. 交付说明

使用简短中文提供：

1. 新增/更新的节点名称和数量。
2. 管理连接与业务路径示意，包括 frp/VLESS 的角色。
3. 当前测试模式、自动周期、任务范围和线路分析开关。
4. 本次是否执行测试；执行过则说明结果、时间和方法。
5. 尚缺的信息、不可测的段，以及推测的线路标签。

不得泄露凭据，不得把“配置成功”写成“线路已实测”，不得把保存中转拓扑写成已改变实际网络路由。

## 7. 已实现接口与导入工具（schemaVersion=1）

所有请求发往本地 Hub（默认 `http://127.0.0.1:50000`）。启用 ADMIN_TOKEN 时带 Bearer 认证。公开状态不返回密码、UUID、公钥参数或密钥路径。

- `GET /api/local`：返回 config、profiles、active、lastRound、nextAt、results、history、asn。
- `PUT /api/local/config`：部分更新 `{ mode: "manual"|"auto", intervalSec: 60..86400|null, scope: [服务器ID], remote: false, routeAnalysis: { enabled: false, withAuto: false, refreshSec: 300..604800 } }`。自动模式必须有非空范围和周期。
- `PUT /api/local/profiles/:id`：更新 `{ methods: ["icmp","tcp","ssh-banner","vless"], endpoint: {host,port}, ssh: {host,port,user,identityFile,jump?}, managementVia: [服务器ID], businessVia: [服务器ID], disabled: false, note, vless?, sshPassword? }`。
- `vless` 和 `sshPassword` 只作为写入字段。省略表示保留，显式空字符串表示删除。不要把掩码重新提交为真实凭据。`identityFile` 需本地绝对路径，SSH 用户与地址会校验。
- `POST /api/local/rounds`：`{ scope: [服务器ID], kind: "latency"|"route", remote: false }`。remote=true 时按连接档案中的中转边双向测量，有直达地址且源端有 SSH 才可执行。
- `POST /api/local/stop`：停止当前任务，不改变自动模式。
- 创建服务器用 `POST /api/servers`；未知位置可只提供名称和已有地址，新增本身不发起网络定位。

可重复导入：`node scripts/import-local.mjs /绝对路径/nodes.private.json`。

```json
{
  "nodes": [
    {
      "key": "my-stable-node-key",
      "name": "示例节点",
      "ip": "192.0.2.1",
      "profile": {
        "methods": ["icmp", "ssh-banner"],
        "endpoint": { "host": "192.0.2.1", "port": 22 },
        "ssh": { "host": "192.0.2.1", "port": 22, "user": "monitor", "identityFile": "/本机路径/id_ed25519" },
        "managementVia": [],
        "businessVia": [],
        "disabled": false
      }
    }
  ]
}
```

导入文件的中转数组填写同一文件中节点的 `key`，工具会转换成服务器 ID。key 在后续更新时保持不变。通过 `local-key:<key>` 标签定位已有记录，不改变自动范围。包含密码或 VLESS 的源文件必须放在 Git 忽略的 data 目录或仓库外，并设为 0600。


- 用户要求补齐地图位置时，对独立公网 IP 调用 `POST /api/servers/:id/locate`，结果标记 `locSource=geoip`（约略位置）。不得定位 frp 入口后把结果写成后端设备位置。无坐标节点必须显示在地图待定位区，不得静默消失。

- 对内网设备，用户授权登录查询时，使用既有接入方式运行有限的只读命令，获取实际公网出口。随后调用 `POST /api/servers/:id/locate`，body 为 `{"egressIp":"查得的 IP"}`。此接口只更新地图位置，标为 `egress-geoip`，不改变节点直达地址或测试范围。出口位置不能声称是设备物理位置。

## DIRECT 测量（2026-10-02）

- 使用 VPN/TUN 时，不可把无 HTTP 代理等同于直连。选择实际物理网卡作为 `directInterface`，保持 `proxyTests: false`。应用层代理、VLESS 与 DIRECT 结果必须区分。
- 本机 macOS 的 ICMP 与逐 TTL 探测使用 `ping -b`；TCP、frp、SSH 通过本地 `scripts/direct-socket.py` 使用 `IP_BOUND_IF` 绑定物理网卡。Python 只在本机运行，无需远端安装。绑定失败即失败，禁止回退 TUN。
- DIRECT 当前只支持明确 IPv4 地址，避免系统 Fake-IP DNS。更换网络时检查网卡与地址。Linux 网卡绑定可能需要权限，未验证平台不得声称已绕过 TUN。
- `proxyTests` 为显式可选项，默认 false。开启后 VLESS 结果属于代理体验，不属于 DIRECT。
- 地球、平面、线路三种视图使用同一套本地连接数据。内网设备的 frp/SSH 端到端结果单独显示，不把它赋给某条内部链路；远程回程结果单独标注方向。

## frp 分段测量

- 接入 frpc 节点时，从其现有配置核对 `serverAddr`、`serverPort`，将 `{host,port}` 保存到连接档案 `frpServer`；同时设置 `managementVia` 指向 frps 节点。只读取这些字段，不输出认证 token。
- `remote=true` 的手动或自动轮次会经现有 SSH 入口登录 frpc，再测 frps 地址的 Ping 往返延迟。源端无 ping 时，用已有 Python 测 `frpServer.port` 的 TCP 建连耗时；不得误用 SSH 端口。
- 图上“frp · 延迟”表示 frpc→frps 分段实测，“端到端 · 延迟”表示本机经映射访问后端的 SSH 响应。方法和方向放在详情，不复制反向测量，不以端到端耗时替代分段 RTT。
- frpc→frps 的 Ping/TCP 衡量两端之间的网络或新建连接，不是现有 frp 会话内部的协议 RTT。不把分段相减作为隧道开销。
- 没有反向直达地址时不伪造 frps→frpc 结果；有客户端主动测试结果即可显示该方向的边，不再叠加未测的反向规划边。

## 发布隐私约束

- 当前用户节点的限制、待启用状态和例外只保存在本地 data 中。接入前结合本地档案和用户最新指示核对，公共 AGENTS.md 不记录真实节点。
- 发布前检查暂存区；不得提交 data、真实 IP/端口组合、登录信息、VLESS 凭据、私有拓扑、实测报告或含这些信息的截图。

# 本地测量与线路分析方案

状态：0.3.0 本地模式已实现。更新日期：2026-10-02。

本文说明本地模式的行为。默认本地模式不运行旧 Hub 自动探测、自动带宽和告警评估；旧功能通过 `NP_MODE=legacy` 显式启用。真实节点未测试前不得标记已验证。部署后的真实连通性需要用户主动执行测量；私有测量记录不随源码发布。

## 1. 目标

- 在指定的本地电脑运行 Hub、测量调度器和界面。默认仅监听回环地址。
- 展示本机到所有已接入 VPS 的连接、延迟和中转关系。没有地理位置的节点仍列入清单，不因无法画地图而漏测。
- 支持公网直连、VLESS、frp、SSH 跳板和已配置隧道。管理连接与业务连接分别记录。
- VPS 不要求安装常驻探针。本地程序通过 SSH 在源 VPS 执行短命令，测试后退出。
- 智能体负责首次配置和后续节点接入。程序负责手动任务及已启用的自动任务，不调用模型。
- 带宽测试不属于本方案的常规测试轮次，不自动运行 iperf3。

## 2. 开关与操作

### 延迟测试

- 初始模式为 `manual`。打开页面、启动服务、重启服务、导入节点、保存配置均不自动发起延迟测试。
- 提供“测试一轮”“测试选中节点”“停止本轮”操作。手动执行不改变调度模式。
- 提供“自动测试”开关和“每隔多久测试一轮”输入框。支持秒、分钟、小时，统一保存为秒。
- 周期范围建议为 60 秒至 24 小时。首次开启必须明确选择周期，不把表单预填值视为开启授权。
- 开启或修改周期后，下一轮从保存时间加周期计算。需要立即测试时，另用“测试一轮”。
- 全局最多运行一轮。轮次超过周期时跳过重叠触发，不排队补跑。手动重复触发返回当前轮次。
- 关闭自动测试会取消后续定时任务；正在执行的轮次继续完成，界面明确提示。用户可用“停止本轮”取消当前任务。
- 服务重启或电脑从休眠恢复后不补跑遗漏轮次。手动模式保持手动；自动模式从恢复时间重新等待一个周期。
- 网页关闭不停止已启用的自动调度。本地服务停止或电脑休眠时无法测量。
- 自动轮次默认只包含用户选定的节点及线路段，不默认执行所有 VPS 两两互测。
- 新增节点默认不进入已有自动任务范围。已有任务范围必须显式保存节点或线路 ID，不能用隐式“以后所有节点”扩张范围。

### 线路分析

- 独立开关 `routeAnalysis.enabled`，初始为 `false`。
- 关闭时不发起新的 traceroute/MTR 或线路识别查询。保留历史结果，并显示时间和“分析已关闭”。
- 开启只启用能力，不立即发包、不自动开启延迟测试。用户可手动“分析线路一轮”。
- 可选择“随自动测试更新线路”，初始关闭。仅在自动测试和线路分析均开启时生效。
- 路由刷新最小间隔默认 6 小时，可另行设置。延迟轮次每分钟执行，也不代表每分钟执行路由探测。
- 关闭线路分析时取消该类排队任务，并终止可取消的在途路由命令；普通延迟任务继续。
- 显示线路名称的开关只控制显示，不控制测量。不得把隐藏标签误当成关闭探测。
- 本阶段不增加异常触发的隐式探测。任何后续异常补测功能必须有显式开关和冷却时间。

## 3. 测量方法

| 对象 | 方法 | 结果名称 |
| --- | --- | --- |
| 本机到 VPS 公网地址 | 系统 ping，默认 3 个包；按配置可使用纯 TCP connect | ICMP RTT / TCP 建连耗时 |
| VPS A 到 VPS B | 本地 SSH 登录 A，在 A 上 ping B，默认 5 个包 | A→B ICMP RTT |
| VLESS | 本地代理内核使用指定出站，向固定目标发送小请求 | 代理端到端响应耗时 |
| frp 映射后端 | 经映射入口等待 SSH banner、完成协议握手或发送小型 HTTP 请求 | 后端响应耗时 / 服务可达性 |
| 公网路由 | 在指定源机器运行有限跳数、有限次数的 traceroute；MTR 为可选诊断 | 可见路由与网络归属 |

- ICMP、TCP、代理响应和 SSH 服务响应分别保存，不能混为同一组 RTT。
- ping 不通不直接证明服务离线。TCP connect 被拒绝可证明主机有响应，但必须标记端口拒绝，不能标记服务可用。
- TCP 检测使用真实建连方法，不向 SSH 等非 HTTP 端口发送 HTTP GET。
- 不使用 SSH 登录总耗时作为 VPS 之间的延迟。计时来自源 VPS 执行的测量结果。
- A→B 与 B→A 分别记录。没有反向结果时显示未知，不复制正向结果。
- 代理测试固定目标、请求方法、字节上限和计时起止点。保存目标和计时定义，避免比较不同口径。
- 本地代理内核需要支持导入链接的协议、传输和安全参数。不支持时显示具体原因，不静默降级。
- 每项任务有次数限制、连接超时、总超时和输出上限。建议本地并发上限 4，SSH 会话并发上限 2；远程每个源节点批量执行，避免每个目标新建登录。
- 路由探测建议最多 30 跳、每跳 1 次、总超时 90 秒。缺失节点保留为未知；不能无限重试。
- 失败重试最多一次，随后等待下轮。前轮未完成时不叠加。
- 不具备测量依赖、凭据或地址的节点标记“不可测”，不阻塞其他节点。

## 4. frp、VLESS 和真实中转

- 拓扑区分设备、服务端点和转发段。同一个公网 IP 的不同 frp 端口可能通向不同设备，不能按 IP 合并。
- frp 至少记录 frps 所在节点、frpc 所在节点、代理类型、公开入口、后端地址与端口；STCP/XTCP 等还需记录 visitor 和实际访问方式。
- frpc 与后端可以不是同一台设备。配置为 `127.0.0.1` 时结合容器/网络命名空间判断，不自动等同宿主机。
- 示例：本机 → A:6000 → frp → B:22。A:6000 的 TCP 建连成功只说明入口响应，完整检测必须接触 B 的服务。
- frp 隧道方向及底层 TCP/KCP/QUIC 等传输按实际配置保存。不能仅凭访问链示意推断底层连接建立方向。
- 测隧道段时使用对应的隧道地址或实际业务路径；对公网 IP 的 ping 不自动代表隧道性能。
- VLESS 链接通常说明入口配置。服务端的出站链、分流和落地关系需要授权读取配置或由用户提供。
- frp 只承载 SSH 管理时，不画入 VLESS 业务路径。代理的请求目标不同可能选用不同出站，需保存测试目标及匹配的出站。
- 保存拓扑只代表配置记录，不执行端口转发、修改防火墙或切换业务线路。“采用”按钮改为“保存规划”，实际路径验证另有状态。
- 各段 RTT 之和仅为分段估算。即使每段都实测，也不能标成整条链路的实测值；完整链路另测端到端响应。

## 5. 网络线路识别

线路分析使用版本化规则和 IP/ASN 数据，不需要智能体。

| 网络标签 | 主要网络特征 |
| --- | --- |
| 电信 163 / ChinaNet | AS4134 |
| 电信 CN2 | AS4809，或 APNIC 登记的 CN2-BB 骨干接口地址 59.43.0.0/16 |
| 移动 CMI | AS58453 |
| 移动 CMIN2 | AS58807 |
| 联通 9929 | AS9929 |
| 联通国际 | AS10099，单独展示，不等同 AS9929 |

- 保存响应 IP、ASN 查询来源、数据库版本、原始跳点顺序和判断依据。IP 的网络归属是证据，不是每一段真实承载路径的绝对证明。
- BGP 公告前缀不能覆盖全部路由器接口。分类器 v2 增加 [APNIC CN2-BB 登记](https://rdap.apnic.net/ip/59.43.0.0/16)（2026-10-02 核对），保存为独立的登记证据，不将登记规则伪装成 ASN 查询结果。规则升级重新解释已保存跳点，保留原采样时间，不自动发起测试。
- 地图主标签显示“去程见某网络”和延迟；Ping/ICMP 是测量方法，放在测量详情中，不当作运营商线路名称。出现 163 跳点不代表整条路径只走 163。
- 展示“检测到某网络”“符合某特征”“证据不足”。不根据单个 IP 前缀、低延迟或供应商名称判定整条线路。
- CN2 GIA 是需要额外佐证的服务标签。观察到 AS4809 只能标记 CN2；GIA 使用“服务商标称”或“符合 GIA 路径特征”，不能自动认证产品等级。
- 多种网络并存时按段展示，不强制给整条路径选一个名称。去程、回程、IPv4、IPv6 分别保存。
- 回程探测到用户公网出口不等于到达内网设备。用同运营商参考地址代测时，明确显示参考目标。
- 中间跳不回包不等于业务丢包；不把中间跳 RTT 相减当成相邻设备的准确延迟。
- 代理、frp 和隧道可能隐藏内部路径，输出未知部分，不编造隐藏节点。
- 默认本地 ASN 数据库。数据库更新可单独配置；在线查询须明确启用，并说明会提交被查询的 IP。

资料参考：

- [电信 ChinaNet / CN2](https://ipms.chinatelecomglobal.com/secure/index.html)
- [移动 CMI / CMIN2](https://mainwebapi.cmi.chinamobile.com/uploads/template/20251216272c9a10af6d23e3b7c459e04e91bf4b.pdf)
- [frp TCP / UDP 转发](https://gofrp.org/en/docs/features/tcp-udp/)

## 6. 数据与程序接口

- 复用 `servers` 的稳定节点 ID；同一设备的公网、SSH、VLESS、frp 地址作为不同端点保存。
- 新增连接档案：节点 ID、用途、协议、入口、后端、跳板、凭据引用、配置来源和验证状态。
- 扩展 `routes`：逻辑节点、端点、连接方式，以及 `planned` / `configured` / `verified` 状态。旧记录迁移后不得直接标记 verified。
- 新增本地测量配置：`mode=manual`、`intervalSec=null`、`scope=[]`；线路分析配置：`enabled=false`、`withAuto=false`、`refreshSec=21600`。
- 测量结果包含：任务 ID、源端、目标端、地址族、接口/代理上下文、方法、样本数、结果、错误、开始/结束时间。
- 每种测量方法单独定义统计值。没有样本时为 null，不能用 0 代表成功。
- 线路结果包含可见跳点、检测网络、证据、产品标称、置信等级、规则版本和采样时间。
- 本机起点绑定实际测量主机。别的手机或电脑访问页面时，仍显示该测量主机名称；浏览器定位不改变起点。
- 已实现 API：`GET /api/local`（schemaVersion=1）、`PUT /api/local/config`、`PUT /api/local/profiles/:id`、`POST /api/local/rounds`、`POST /api/local/stop`。字段见节点接入流程。
- 所有配置入口经 `config.js` 校验。创建任务和修改配置要求管理员认证。本地监听也要防止任意网页跨源创建任务。
- SSH 密钥保留在本机，使用 ssh-agent 或私有凭据引用。VLESS 凭据保存在受限的本地文件；不得进入 Git、日志、公开 API 或普通导出。
- SSH 使用参数数组、固定任务模板和参数校验。远端 shell 参数也必须安全引用。不能把 UI 输入或 Hub 文本直接拼成任意命令。
- 保留 SSH 主机密钥校验。依赖安装、账户或业务配置变更不得作为自动检测的副作用。

## 7. 实现位置与后续维护要求

1. `server/monitor.js`：新增本地模式调度控制。不能让旧 `startMonitor()` 继续在启动时及每 15 秒主动探测。
2. `server/agentbus.js`：本地模式不得因旧 `autoHours` 启动带宽任务。现有 VPS Agent 保持单独的旧模式；本地开关不能声称已停止远端独立服务。
3. `server/config.js`、`store.js`：新增配置、档案和结果结构。进入新模式时默认手动，并保留可恢复的旧配置，不删除旧数据。
4. 新增本地调度、系统命令适配、SSH 测量、代理测试和线路识别模块。优先系统工具；缺少工具时展示缺项。
5. `server/index.js`：增加版本化管理接口、任务取消和状态推送。本地模式明确配置回环监听。
6. `src/routes.js`：区分方向、方法和数据来源；分段相加保持估算；停止把参考目标反向结果当作本机实测。
7. `src/ui/routes.js`、设置页：增加开关、周期、范围、手动执行、停止、下次运行时间和过期提示。删除“保存规划即切换线路”的误导文案。
8. 结果新鲜度按采样周期和方法计算。不能沿用固定 90 秒 Agent 过期阈值判断 5 分钟 SSH 测量，更不能把未测、过期直接当离线。
9. 历史保存设置数量/时间上限，批量落盘；未启用任务时无每秒轮询或命令启动。

## 8. 验收要求

- 手动模式下启动、重启、打开页面、保存配置、添加节点均无主动测试流量；旧 Hub 探测和带宽定时器不能绕过开关。
- 开启线路分析不会启动定时任务；关闭后不会发起新的路由任务。历史仍可查看。
- 手动一轮只执行所选任务，完成后不继续。自动模式按用户周期执行，关闭网页仍运行。
- 验证超时、失败、取消、任务重叠、休眠恢复和重启；不出现补跑风暴或遗留远端后台任务。
- 新增节点保留已有 ID、线路和周期，默认不进入自动范围；重复导入同一端点不产生重复节点。
- 至少验证直连、SSH 跳板、frp 映射、VLESS 实际请求四种路径。入口通而后端不通时显示后端失败。
- 缺少 SSH 权限、代理内核、路由工具或 ASN 数据时显示具体限制，不返回伪造延迟或确定线路标签。
- 去程/回程、IPv4/IPv6、分段估算/端到端实测、标称/检测到的网络均能区分。
- 普通导出、页面状态和日志不含访问凭据。节点接入流程可由另一个智能体根据文档独立完成。

后续接入操作见 [节点接入 AGENTS.md](node-onboarding/AGENTS.md)。


## 9. 部署限制与隐私

- 用户节点清单、IP、登录入口、中转拓扑、来源页面、位置及实测记录只保存在 Git 忽略的本地 data 目录，不写入公共文档、测试或截图。
- 公网路由以可见跳点作为证据；不能凭标签认证 GIA 产品等级。MTR 专用诊断尚未实现。
- 地理位置需要注明来源与约略性质；不使用 frp 入口位置代替后端位置。
- 无直达地址的内网反向段保持不可测。远端不安装软件；缺 ping 时可使用已有 Python 做 TCP 建连测量。
- SSH 会话可能产生服务器正常访问日志，不会抹除系统日志。

## 10. 连线标签与 frp 分段修正

- “线路 / 延迟”是三种视图的标签总开关；关闭时悬停和选中不能绕过开关。未测本地分段保留连线，不显示“frp · 未测”。
- frpc→frps 经远端现有工具主动测量，frps 实际地址和端口保存在 `frpServer`。本机→frpc 经映射得到的 SSH 服务响应另标“端到端”。
- 关闭标签仅影响地图展示，不取消测量、不删除结果。打开标签也不发起测量。

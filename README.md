# 🌍 Network Planet

用 Three.js 3D 地球实时展示你遍布全球的 VPS：位置、在线状态、CPU/内存/网速、服务器之间的连接、延迟、丢包与带宽。

- **3D 地球**：离线生成的矢量世界地图（Natural Earth），带大气层光晕和星空；滚轮按「离地高度」缩放，可以一路放大到城市级别
- **同城多台自动聚合/展开**：比如洛杉矶有 5 台，远看是一个「洛杉矶 5」的聚合点；滚轮放大到城市级别、或者点一下聚合点，它们会以「蜘蛛腿」的方式在屏幕上散开，每台都能单独点选
- **实时状态**：Hub 定时对每台服务器做 TCP 探测（无需安装任何东西）；装上探针（Agent）后还能看到 CPU / 内存 / 磁盘 / 网速 / 连接数，SSE 每 3 秒推送一次
- **探针一条命令通装**：所有 VPS 用同一条命令，装完自动出现在地球上（已导入的机器按 IP 自动认领）
- **三网延迟**：每台机器测到电信 / 联通 / 移动（及任意自定义 IP、域名）的延迟和丢包，支持 ICMP / TCP / HTTP
- **带宽测试**：任意两台之间一键 iperf3 测速（双向），也可以定时自动测
- **流量统计与告警**：按每月重置日累计流量、对比套餐额度；离线 / CPU / 内存 / 磁盘 / 流量 / 三网延迟 / 到期 告警，推送到 Telegram、钉钉、企业微信、飞书、Bark 或任意 Webhook
- **流量周期与历史图表**：每台机器可以单独设置重置时刻（精确到分钟）、每月 / 每 N 天 / 不重置、商家结算时区；按任意时间段查看用量（按小时 / 天的柱状图），看本周期累计曲线、额度线和「按当前速度预计」，以及过去每个周期的用量；CPU、内存、磁盘、负载、网速、延迟都有 24 小时 ~ 400 天的历史曲线
- **全部可配置**：检测间隔、各项检测开关、测速参数、流量计费方式都在网页里改，几秒内下发到所有探针，单台机器还能单独覆盖
- **互联连线**：大圆弧连线，颜色表示实测延迟，光点流动速度对应延迟、数量对应吞吐；没有实测时显示灰色虚线和按距离估算的延迟
- **延迟矩阵**：所有服务器两两之间的延迟热力表
- **手动增删改**：服务器、连接都可以在界面上加/改/删；支持按 IP 自动定位、在地球上点选位置、JSON/CSV 批量导入导出
- **供应商 API 导入**：Vultr、DigitalOcean、Linode/Akamai、Hetzner Cloud、搬瓦工 KiwiVM、通用 JSON URL；拉取后勾选导入，再次拉取会更新 IP/配置/状态

> 首次启动会自动载入一组**演示数据**（24 台、19 条连接，数据为模拟），方便你先看效果。在 ⚙ 设置 →「清除演示数据」一键删除。

## 快速开始

需要 Node.js ≥ 18.17。

```bash
cd network-planet
npm install

# 开发模式：同时启动 Hub(50000) 和 Vite(50001)
npm run dev
# 打开 http://localhost:50001

# 生产模式：构建前端，由 Hub 一个进程托管全部
npm run build
npm start
# 打开 http://localhost:50000
```

### 环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `PORT` | `50000` | Hub 监听端口 |
| `HOST` | `0.0.0.0` | 监听地址 |
| `ADMIN_TOKEN` | 空 | 设置后，界面和 API 都需要这个口令（**部署到公网时务必设置**） |
| `NP_DATA_DIR` | `./data` | 数据目录（`db.json` 存服务器/连接/API Key） |
| `NP_DEMO` | `1` | 设为 `0` 时首次启动不灌入演示数据 |
| `NP_GEOIP` | 开 | 设为 `off` 禁用 IP 定位（ip-api.com）对外请求 |

## 安装部署（手动）

整套由两部分组成：**Hub**（网页 + 数据，部署一份）和 **探针**（每台 VPS 装一个）。探针主动连 Hub 上报，所以 **Hub 必须部署在所有 VPS 都能访问到的地方**（一台有公网 IP 的服务器，或你自己电脑 + 内网穿透）。Hub 跑在只有你自己能访问的电脑上时，只能看演示数据和 Hub 的 TCP 探测结果。

> 机器很多、不想一台台登录？看 [交给 AI 助手批量安装](docs/AI_INSTALL.md)。

### 第 1 步：部署 Hub（一条命令）

**从开发机部署到服务器**（第一次只能这样，因为还没有地方能下载代码包）。在本项目目录执行：

```bash
npm install
npm run deploy -- root@你的服务器IP          # ssh 端口不是 22 就在后面加端口
```

它会本地构建打包、上传，并在服务器上执行 `scripts/install-hub.sh`：
- 没有 Node.js ≥ 18.17 就下载官方二进制装到 `/opt/network-planet-node`（不动系统包；国内机器可加 `NP_NODE_MIRROR=https://npmmirror.com/mirrors/node`）
- 代码装到 `/opt/network-planet`，数据在 `/var/lib/network-planet`，配置在 `/etc/network-planet.env`
- 注册 systemd 服务 `network-planet`，开机自启；ufw / firewalld 已启用时自动放行端口
- **随机生成访问口令（ADMIN_TOKEN）并打印出来**，同时把「Hub 公网地址」自动设为 `http://公网IP:50000`
- 再次执行就是升级：保留口令、配置和数据

**已经有一台 Hub 后**，在任何服务器上一条 curl 就能装一份同样的 Hub（代码包由那台 Hub 现场提供）：

```bash
curl -fsSL http://已有的hub:50000/hub/install.sh | sudo bash
curl -fsSL http://已有的hub:50000/hub/install.sh | sudo bash -s -- uninstall   # 卸载（数据保留）
```

可选变量（加在 `bash` 前面）：`PORT`（默认 50000）、`ADMIN_TOKEN`（默认随机）、`NP_PUBLIC_URL`（Hub 公网地址，用域名时填）。

装好后：
- 云厂商有安全组的话放行 TCP 50000
- 想用域名 + HTTPS，前面套 Nginx / Caddy 反代到 `127.0.0.1:50000`（SSE 需要关闭缓冲，Hub 已发送 `X-Accel-Buffering: no`），再把 Hub 公网地址改成 `https://你的域名`
- 查看状态 `systemctl status network-planet`，日志 `journalctl -u network-planet -f`，口令在 `/etc/network-planet.env`
- 备份 `/var/lib/network-planet` 即可（`db.json` 含供应商 API Key，注意别泄露）

### 第 2 步：确认 Hub 公网地址

用安装时打印的口令登录网页，⚙ 设置 →「通用」→「Hub 公网地址」应该已经是 `http://公网IP:50000`。用了域名 / HTTPS 就改成对应地址，探针安装命令里的地址就是从这里来的。

### 第 3 步：每台 VPS 装探针

顶栏「⤓ 安装探针」→「复制安装命令」，ssh 登录**每台** VPS，以 root 执行（所有机器是同一条命令）：

```bash
curl -fsSL https://你的hub/agent/install.sh | sudo NP_HUB=https://你的hub NP_KEY=注册密钥 bash
```

输出里看到「已注册为 …」和「✅ np-agent … 已运行」就成功了，几秒内这台机器会出现在地图上：

- 已经通过供应商 API 导入或手动添加过的机器，**按 IP 自动认领**，不会重复
- 新机器按公网 IP 自动定位；定位不准就加 `NP_CITY="Los Angeles"`
- 可选 `NP_NAME=显示名`、`NP_TAGS=cn2,proxy`、`NP_PROVIDER=dmit`（加在 `bash` 前面，弹窗里填了会自动拼进命令）
- 同一台机器重装不会重复注册（按 machine-id 识别）
- 也可以用某台服务器详情里的「专属命令」（`NP_ID` + `NP_TOKEN`），直接绑定到那台
- 需要 systemd（Debian / Ubuntu / CentOS / Rocky / Alma / Arch / openSUSE 等都可以，Alpine 的 OpenRC 暂不支持）

### 第 4 步：确认

- 「⤓ 安装探针」弹窗下方的表格里，这台显示版本号、最后上报时间
- 在 VPS 上：`systemctl status np-agent`，日志 `journalctl -u np-agent -f`
- 装好后建议在弹窗里「更换注册密钥」或关闭「允许自动注册」，已安装的探针不受影响

### 升级 / 卸载

```bash
curl -fsSL https://你的hub/agent/install.sh | sudo bash                     # 升级，沿用原身份
curl -fsSL https://你的hub/agent/install.sh | sudo bash -s -- uninstall     # 卸载
```

卸载只删 VPS 上的探针，Hub 上的服务器记录需要在网页里删除。

## 使用说明

### 地球操作

| 操作 | 效果 |
| --- | --- |
| 拖拽 | 旋转地球（越贴近地表转得越慢，方便精确定位） |
| 滚轮 / 双指捏合 / 底栏 ＋－ | 缩放 |
| 双击地表 | 飞到该点并放大 |
| 点击聚合点（如「洛杉矶 5」） | 飞过去并展开同城的所有服务器 |
| 点击服务器 / 连线 | 右侧打开详情 |
| `Esc` | 取消选中 |
| `/` | 聚焦搜索框 |
| `n` | 添加服务器 |

底栏开关：自转、手动连接、实测网格（Agent 测出的全部两两延迟）、连线 ms 标签、服务器名称。

### 同城多台怎么看

1. 远看时同一城市（25km 内）的服务器聚合成一个点，徽标显示数量，红色 `n↓` 表示其中 n 台离线
2. 滚轮放大到大约「一个州」的范围，所有聚合点自动展开；或者直接点击聚合点
3. 展开后的间距按**屏幕像素**计算，任何缩放级别下都不会挤在一起；每台服务器之间的连线也会从各自的位置连出
4. 左侧列表按城市分组，点任意一台会飞过去并选中它

### 添加服务器（手动）

顶栏「＋ 服务器」。位置有四种填法，任选其一：

- 输入城市（中英文都行，下拉里有 100+ 个常见机房城市）
- 「按 IP 定位」：用 ip-api.com 根据 IP 查经纬度
- 「在地球上选点」：弹窗暂时隐藏，在地球上点一下
- 直接填经纬度

只填 IP 也能保存，后端会自动按 IP 定位。

### 通过供应商 API 导入

顶栏「☁ API 导入」→ 选择供应商、填 API Key →「保存并拉取」→ 勾选 →「导入 / 更新选中」。

| 供应商 | 需要的凭据 | 位置来源 |
| --- | --- | --- |
| Vultr | API Key | region 代码 |
| DigitalOcean | Personal Access Token（只读即可） | region slug |
| Linode / Akamai | Personal Access Token（Linodes 只读） | region |
| Hetzner Cloud | 项目 API Token（只读即可） | API 直接给经纬度 |
| 搬瓦工 KiwiVM | 每行一个 `VEID:API_KEY` | node_location_id |
| 通用 JSON URL | URL +（可选）Bearer Token | 数据里的 lat/lon 或 city |

- region 映射不到城市时会退回到按 IP 定位
- 再次「拉取」会标出已导入的实例；导入时更新 IP/配置/状态，但**保留你自己改过的名称、标签、备注和手动设置的位置**
- API Key 只存在 Hub 的 `data/db.json`（文件权限 600），前端只看到打码值。建议都用只读 Token

通用 JSON URL 的格式：

```json
[
  { "id": "la-1", "name": "LA-1", "ip": "1.2.3.4", "city": "Los Angeles", "provider": "dmit", "tags": ["cn2"] },
  { "name": "HK-1", "ip": "5.6.7.8", "lat": 22.32, "lon": 114.17, "specs": { "cpu": 2, "ramMB": 2048 } }
]
```

### 连接（连线）

- 顶栏「⇄ 连接」，或者在服务器详情里点「＋ 添加」
- 服务器详情的「实测延迟」列表里，每一行右侧的 `＋` 可以一键把实测链路保存成连接
- 连线颜色：<60ms 绿 / <150ms 黄绿 / <250ms 黄 / ≥250ms 红 / 灰色虚线 = 无实测（显示估算值）/ 红色虚线 = 中断

### 探针（Agent）

只靠 Hub 的 TCP 探测，你能看到在线状态和 **Hub → 服务器** 的延迟。想看资源占用、服务器之间的延迟、三网延迟、带宽和流量，需要在 VPS 上装探针。

安装步骤见上面的 [安装部署](#安装部署手动)；机器多时也可以 [交给 AI 助手批量安装](docs/AI_INSTALL.md)。「⤓ 安装探针」弹窗里能看到每台的探针版本，旧版本会标「需升级」。

**探针做什么**（`agent/np-agent.sh`，纯 bash + curl，systemd 服务 `np-agent`）：

| 功能 | 默认 | 说明 |
| --- | --- | --- |
| 基础指标 | 每 10 秒 | CPU、内存、Swap、磁盘、网速、累计流量、负载、TCP 连接数、进程数 |
| 服务器互测 | 每 60 秒 | 到其它每台服务器的延迟 / 丢包 / 抖动（ICMP，或 TCP 连对方的「探测端口」） |
| 检测目标 | 每 60 秒 | 默认三网 9 个点 + Cloudflare / Google，可在「检测目标」页增删改，支持 ICMP / TCP / HTTP |
| 带宽测试 | 手动 | 在连线或服务器详情里点「测速」，两端用 iperf3 双向各测 5 秒；可设为每 N 小时自动测「手动连接」 |
| 流量统计 | 每月 1 号重置 | 计费方式可选双向合计 / 只算出站 / 只算入站 / 取较大方向；和服务商面板对不上时可以手动校准 |

以上开关和参数都在 ⚙ 设置 →「探针」里改，保存后**几秒内下发**到所有探针，不用重启；单台机器可以在「编辑 → 探针与告警」里单独覆盖（比如流量小的机器关掉带宽测试）。

**依赖与安全**：

- 安装脚本会尝试装 `ping` 和 `iperf3`（`NP_NO_DEPS=1` 跳过）；没有 ping 时自动改用 TCP 测延迟，没有 iperf3 只是不能测带宽
- 带宽测试要在防火墙放行 iperf3 端口（默认 TCP 5201，可改），而且会**真实消耗流量**（约 带宽 × 时长 × 2）
- 探针以 systemd 临时无特权用户运行，只额外授予 ping 需要的 `CAP_NET_RAW`
- Hub 只能给探针下发**固定格式**的配置和测速任务，所有参数都按白名单校验；**不能**在 VPS 上执行任意命令
- 需要 systemd（Debian / Ubuntu / CentOS / Rocky / Alma / Arch / openSUSE 等都可以，Alpine 的 OpenRC 暂不支持）

### 流量周期与历史图表

不同商家的流量重置规则不一样，所以每台机器可以在「编辑 → 流量周期」里单独设置：

| 重置方式 | 适用 | 填什么 |
| --- | --- | --- |
| 跟随全局 | 大部分「每月 1 号」重置的 | 不用填，全局默认在 ⚙ 设置 →「探针」里改 |
| 每月固定日期和时刻 | 按开通日重置，如每月 15 号 08:30 | 任意一次重置的时间（比如开通时间）。31 号这类日期遇到小月在月底重置，之后仍按原日期 |
| 每隔 N 天 | 30 天 / 28 天一周期 | 任意一次重置的时间 + 天数 |
| 不重置 | 一次性流量包、按量计费 | 从什么时候开始累计 |

「商家结算时区」默认是浏览器时区，商家面板显示的是 UTC 时间就选 UTC+0。流量额度可以填 GB 或 TB，计费方式（双向 / 只算出站 / …）在「探针与告警」里。改了周期后，本周期用量会从已有的历史数据重新汇总，不会清零。

详情面板的「本周期流量」显示周期起止、剩余时间、日均和「预计周期末」用量（会超额时标红），下面的小图是周期累计曲线。点「📊 按时间段查看」或「📈 历史图表」打开大图：

- 时间范围：24 小时 / 7 天 / 30 天 / 本周期 / 上个周期 / 自定义任意起止时间
- 流量柱状图：每小时或每天的入站 / 出站，悬停看具体数值和采样覆盖
- 汇总：区间用量、有效时段日均、最高时段、采样覆盖率、CPU / 内存平均与峰值、在线率
- 本周期累计曲线 + 额度线 + 按当前速度外推的预计线；历史周期列表，点一行就看那个周期
- CPU、内存（平均 + 峰值）、磁盘、负载 / TCP 连接、网速（平均 + 峰值）、Hub 延迟与不在线比例

历史数据由 Hub 自己记录（`data/history/<服务器id>.json`），5 分钟粒度保留 8 天，1 小时粒度保留 400 天，每 5 分钟落盘一次。流量按 Agent 两次上报之间的累计计数增量计算，跨小时 / 跨天的增量按时长比例分摊；Agent 离线期间的流量在它重新上线后补记（计数器没重置的话），但不算「采样覆盖」。

### 平面视图与线路模式

底部视图条最左边切换 **🌐 地球 / 🗺 平面 / 🧭 线路**（会记住上次的选择）。

**平面视图**：点阵世界地图，适合一眼看全局。
- 默认显示整张世界地图。拖动平移，滚轮 / 双指缩放，双击放大，◎ 复位到全图。经度方向无限循环，跨太平洋的线路不会被切断。
- **🔒 锁定**：只显示一份世界地图，不再左右循环。仍然可以缩放和拖动，但最多缩到整张图铺满，拖动也不能越过地图左右边缘（适合挂在大屏上）；跨地图边缘的线在边缘截断。
- 服务器附近的陆地点会染成它的颜色；夜半球的点稍暗（实时晨昏线）。
- 连线是拱形弧线：颜色代表实测延迟，流动点越快延迟越低，光点越多吞吐越大；中间的胶囊显示「备注 · 延迟」。
- 屏幕上挤在一起的机器会合并成带数字的节点，点一下拉近；同机房拉不开时直接环形展开。

**线路模式**：从一个起点扇出到每台 VPS，看怎么走、哪些要中转。
- 起点可以是：
  - **本机**：延迟用 Hub 测到各台的数据，Hub 跑在你自己电脑上时就是本机延迟。位置在面板右上 ⌖ 里设置，可以选城市、浏览器定位或在地图上点。
  - **某台服务器**：用 Agent 之间互测的延迟。
  - **某个检测目标**（比如「上海电信」）：用各台 Agent 测这个目标的延迟，相当于「从这个运营商出发」。
- **自定义线路**：起点 → 中转 1 → 中转 2 … → 终点，每一段可以写标签（专线 / IPLC / hysteria2 / WG…）。每段延迟取实测，没实测的按距离估算并标 ≈。总延迟是各段之和，并和直连对比快了还是慢了多少。
- **推荐中转**：在实测数据上找最短路（最多 2 个中转，每多一跳额外算 2ms 转发开销）。直连不通，或者中转能省 20% 以上且至少 15ms，就给出「建议经 X 中转」，点「采用」即保存为线路。
- 悬停或选中一台，会高亮从起点到它的整条路径。
- 线路保存在 Hub（`db.json` 的 `routes`），导出 JSON 时一并带上。删除服务器时，引用它的线路会一起删除。

### 告警

⚙ 设置 →「告警」：

- 规则：离线、CPU、内存、磁盘、流量（占套餐的百分比）、检测目标延迟 / 丢包、到期提醒，阈值和持续时间都可调
- 渠道：Telegram Bot、Webhook（通用 JSON / 钉钉 / 企业微信 / 飞书 / Bark），可以「保存并发送测试通知」
- 顶栏 🔔 显示正在告警的数量，点开能看到告警事件记录；单台服务器可以在编辑里设为「不发告警」
- 演示服务器不参与告警

### 导入 / 导出

顶栏 `⇅`：导出全部服务器 + 连接为 JSON（不含 Token 和 API Key）；导入支持 JSON 或 CSV：

```csv
name,ip,city,provider,tags,lat,lon
LA-1,1.2.3.4,Los Angeles,dmit,cn2|proxy,,
HK-1,5.6.7.8,,aliyun,,22.32,114.17
```

## 常见问题

**服务器显示「未知」？** Hub 还没探测到（默认 15 秒一次），或者探测端口不对。在编辑里把「探测端口」改成该机器一定开放的端口（如 22 / 443）。显示「离线」说明 TCP 连接超时且没有 Agent 上报。

**连线是灰色虚线？** 两端都没有 Agent 实测数据，显示的是按大圆距离 × 1.6 绕行系数估算的延迟。

**三网延迟全是「不通」？** 默认目标是各地运营商的 DNS 服务器，有的会屏蔽 ICMP 或境外访问。在「检测目标」里换成别的地址，或改用 TCP / HTTP 方式。

**带宽测试失败？** 看提示：「没有安装 iperf3」就重新运行安装命令；「连不上对方 iperf3 端口」就在对端防火墙 / 安全组放行 TCP 5201（或你设置的端口）。

**探针装上了但没数据？** 在 VPS 上 `journalctl -u np-agent -f` 看日志，多半是 Hub 公网地址填错或被防火墙挡了。

**地球放大后不够清晰？** 贴图分辨率 8192×4096；放大后海岸线和国界会切换为矢量线，始终清晰。

**能加别的供应商吗？** 可以，参考 `server/providers/vultr.js` 写一个 `{ id, name, fields, list(credentials) }` 模块，在 `providers/index.js` 注册，再在 `regions.js` 补上 region 映射。AWS/GCP 这类需要签名的 API 也可以用「通用 JSON URL」配合自己的导出脚本。
